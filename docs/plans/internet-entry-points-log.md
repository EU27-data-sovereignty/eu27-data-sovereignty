# The internet entry points: what was done and decided

A log of the work behind [`INTERNET-ENTRY-POINTS.md`](../../INTERNET-ENTRY-POINTS.md), newest first, in the shape of
[`technical-universities-log.md`](technical-universities-log.md). Each entry records who or what produced it, what the
owner asked, what was decided and why, what changed, how it was checked, and what is still open. The decision of record
is `DECISIONS.md` #109; this log is the working narrative behind it, not a second copy. Planning, not data: nothing here
is read by the model, the book, the web app or `/ask`.

## 2026-10-14 — the note written from two fetched lists, its counts derived, reviewed twice

**Produced by.** Claude Fable 5.1 (`claude-fable-5-1`) in Claude Code, session
`https://claude.ai/code/session_01MU2Nipp3HgoYjhpF2Sxhi7`, in the worktree branch `worktree-notes-internet-entry-points`
from `fcf0b65` (`origin/main`), while another session was committing the mobile reader (#109 to #113) in the main
checkout. Three explorer agents mapped the note contract, the fact pipeline and the workspace's earlier cable work; one
planning agent probed the candidate sources with plain HTTP; the rows were generated by a script in the session's
scratchpad from the fetched JSON. The reviews are listed under "The reviews" below as each one reported.

**Asked by the owner.** "we need to document where 'the internet' 'enters' each country , e.g. key entry and choke
points".

### Decisions

1. **An authored note, not a sourced register.** The project already carried this topic as the unsourced `ixp` column of
   `model/eu27_parameters.csv`, printed as *Not yet sourced* in every brief. A sourced register would need a new claim
   namespace, staging, review, admission and the cross-model fact-check gate before it could reach `main` (the #96
   operators plan, still unbuilt, is the template), and `national_data.csv` holds one row per state and class, which
   cannot hold a list of stations. The authored-note contract of #103, #104 and #108 ships in one session and is held by
   a checker. Recorded as #109 with the register as the *would change if*.
2. **"Key" and "choke point" became three counted terms.** The project ranks nothing (#10, #77) and a judgement of which
   entry is key is an opinion no reader can check. The note defines no-landing, single-landing and single-exchange as
   counts of the rows and says in one sentence that those are its only reading of "choke point". The checker refuses the
   terms anywhere else and refuses ranking and size words ("largest", "major", "hub", "key", "gateway") in prose and
   Place cells.
3. **Counts are derived, never typed.** Every state's table ends in a `Counts:` line; `./run.sh entry-points counts`
   writes it from the rows and `check` fails on a line that differs. The author never types a number. The Method section
   quotes the totals the checker printed and names the states each term applies to, which a reader can verify against
   the Counts lines.
4. **Every entry the two lists give is a row; no cap.** A capped "main" list per state would need a selection rule, and
   any rule is a ranking by proxy. IT has 55 landing points and DE 59 exchanges; that is the lists' fact.
5. **E1 cites the map's JSON page, never its HTML.** The Submarine Cable Map's `/landing-point/<slug>` pages are a
   1.5 KB application shell with no text; a row citing one could never be checked against its served bytes. The map's
   `api/v3/landing-point/<slug>.json` carries the name and the cables, so the checker pins that host and path. The same
   holds for PeeringDB: its `/ix/<id>` HTML carries the name, city and country.
6. **Names are the cited page's own words; the word and figure rules fall on Place and prose.** PeeringDB has a "TOP-IX"
   and a "FICIX 1 (Espoo) IPv6 MTU 9000"; refusing them would mean rewriting the source. The first checker draft applied
   the ranking regex to Name cells and was changed when the generated rows tripped it.
7. **Satellite gateways are out.** No published list names earth stations per state in a way a row could cite.
8. **E3 only from the registry.** One row, Latvia's Article 32, already cited for indicator LV:L1. No search for other
   statutes was run, and the note says a state without an E3 row has not been searched; E3 therefore has no "none" row.
9. **The licence is quoted, not asserted.** The first draft said the map's data is CC BY-SA 4.0 "as stated in the map's
   own code". The same-model review fetched the bundle and the page it links to: the code licenses "any reference to
   TeleGeography's Submarine Cable Map, URL, or any screencapture of the map" under CC BY-SA 4.0, states no licence
   for the data behind the JSON pages, and TeleGeography's citation page says the underlying databases remain
   restricted to paying subscribers. The note, `LICENSE-DATA` and #109 now quote the sentence, say the data's licence
   is not stated, keep attribution and share-alike as the conservative reading, and put the ruling to the owner before
   any push (`TODO.md`). If the terms do not allow reproduction, the E1 rows are withdrawn and the note keeps E2 and E3.
10. **Separate worktree.** Another session was committing in the main checkout, so the work ran in
    `.claude/worktrees/notes-internet-entry-points` off `origin/main`. The entry is numbered #109, the next free
    number on `origin/main` at the time; the mobile reader's uncommitted entries also start at #109, so whichever
    branch merges second renumbers (this one to #114 if the mobile reader goes first; `tests/test_docs.py` holds
    the sequence).

### How the research ran

- Probes on 2026-10-14 with plain HTTP, before any row: the map's HTML pages (empty shell), its JSON pages (names and
  cables present), PeeringDB's HTML and API (name, city, country present; no key needed), Euro-IX's list pages (404; its
  IXP-DB API answers but has no page per exchange), the Latvian statute (already in the registry).
- `fetch_enum.py` (scratchpad): one fetch of the map's landing-point index; 319 landing-point JSON pages, one per point
  the index labels with a member state; 27 PeeringDB queries, one per country code (GR for Greece); one IXP-DB list.
  Every response kept as fetched.
- `gen_rows.py` (scratchpad): the 27 sections as a pure function of those files, rows sorted by Kind then Name, "none"
  rows where a list gave nothing, the Counts line from the module's own `counts_line`. It also printed what the Method
  needed: planned cables without a year, exchanges without a website, names the checker would refuse, seed names from
  the `ixp` column that no fetched page carries, and the IXP-DB comparison.
- The header, Definitions and Method were written by hand around the generated sections; `counts` was then run and
  changed nothing (idempotent on a generated note); `check` was green but for the register; `links` fetched every URL.

### The reviews

1. **Second-agent review, same model** (`claude-fable-5-1`, fresh context, 2026-10-14). Fifteen findings, three
   blocking: 162 E2 rows cited a PeeringDB page the register showed answering 429 while the Method promised an
   [unverified] mark for a page that did not answer (fixed by the sequential `retry` and the register rerun; see
   Verification); the README and this log described the reviews as done before they had run (rewritten to record
   each review only once it reported); and the CC BY-SA sentence attributed to the map's code a licence on the data
   that the code grants only to references, URLs and screen captures (decision 9 above). Four stated rules the checker
   did not hold were added to it: an E3 page must be in the source register; an E1 label must end with the state's
   name; an [unverified] E1 row is not in service in the Counts line; the hand-typed totals in the Method are now
   named as the checker's printed totals and the claim "no count typed by hand" is narrowed to the Counts lines. The
   word scan gained plurals and "main", "primary", "central", "principal", "backbone", strips quoted phrases instead
   of exempting whole lines, and exempts the satellite line by name. Confirmed by the reviewer: the E1 rows equal the
   map's live index, 319 of 319, no `is_tbd` point among them; every Counts line matches its rows; no ranking word in
   the prose; the cable split and the Counts rewrite are correct; the CY row's seven cables and flags match the live
   page.
2. **Cross-model check** (`claude-opus-5-5`, 2026-10-14, #87's standard: the model that did not write it). Its own
   scripts and raw pages are in the session scratchpad (`xcheck/`), not in the repository. 646 fresh fetches, all
   200: the map index, 319 landing-point JSON pages, 27 PeeringDB API lists, 299 PeeringDB HTML pages, the statute.
   E1: the index's 319 labelled points equal the note's rows per state, no point missing and none extra; every Name
   equals the JSON name and every cables cell equals the JSON cable list with the planned suffixes, 319 of 319. E2:
   the API id sets equal the note's per state; every Name in the page title, Place and website as the page and API
   give them, 299 of 299. E3: the phrase on the page. The seven "none" rows true. All 27 Counts lines recomputed from
   the cells and again from the JSON's planned flags. Zero discrepancies. Prose: the same licence overreach and the
   same 429 rows as review 1; "French overseas territories" misdescribed the outermost regions and hid the asymmetry
   with the Canaries, Madeira and the Azores; "on the state's territory" was the note's phrase for a label that also
   covers offshore platforms and Bonaire; the map holds four more Bonaire points under "Bonaire, Sint Eustatius and
   Saba". All four rewritten in the E1 definition; no row changed.
