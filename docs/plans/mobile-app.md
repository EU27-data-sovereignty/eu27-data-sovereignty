# Plan: a mobile app in all 24 EU languages (React Native + Supabase)

Drafted 2026-10-03 by a read-only planning agent and reviewed in session. Nothing in it is decided until the
owner answers the decisions at the end, and each choice that closes off an alternative gets a `DECISIONS.md`
entry.

## Context

- **The current reader.** `mobile/` is a stale Expo reader of about 1,140 lines, built on the withdrawn
  schema-1 bundle. It carries 4 Dependabot alerts, which come from the Expo toolchain rather than the app's
  code: `node-forge`, `uuid`, `braces` and `decode-uri-component`.
- **What is worth keeping from it:**
  - `__tests__/security.test.ts`: no permissions, a dependency allowlist, only the anon key may be public;
  - the parity-test idea;
  - `src/services/supabase.ts`: null when not configured, no session;
  - `Colors.ts`, generated by `design/build_tokens.py`.
- **The bundle.** `web/public/data/eu27.json` is schema 2, 6.4 MB. Its printed text is about 1,168 fact
  strings, 168 categorical facts, 223 method strings and 81 labels.
- **Fonts.** Libertinus Serif covers Greek, Bulgarian Cyrillic, Irish and Maltese. React Native needs it as
  TTF/OTF, not the woff2 files the web uses.

## Recommendation

1. **Rebuild `mobile/` rather than port it.** Start from the Expo/EAS skeleton in `templates/rn-supabase`, and
   leave out its auth and form libraries.
2. **Ship the fact-checked bundle inside the app, read-only and offline.** The web's rules hold: renderers
   add no content, every fact is backed as printed, and every screen carries the disclaimer.
3. **No Supabase in v1.** "Check this fact" and "Submit a source" open the same GitHub issue forms the web
   uses.
4. **Supabase comes later, after the foundation exists** (`docs/plans/stichting.md`), to act as data
   controller. Even then, weigh hosted Supabase against self-hosting on an EU provider: Supabase is a US
   company, a credibility question for a report about sovereign hosting.

## Architecture

- **The renderer.** A native `DocumentView`, ported from `web/src/components/DocumentView.tsx`. Shared types
  are kept in parity with `web/src/data/types.ts`.
- **A split bundle.** `model/export_json.py --split` writes:
  - `eu27.core.json`: the index, methodology and fact-check summary;
  - `eu27.<ISO>.json`: one per country;
  - `manifest.json`: the SHA-256 of each part.

  The app loads countries lazily. The web keeps using the single file.
- **About this edition.** The screen shows the bundle hash, the commit, and "N of N checked".
- **Edition check (v1.1).** One GET of `https://eu27.cloud/data/manifest.json`, so an installed app can
  offer a newer edition rather than keep printing facts that were later withheld. This is the app's only
  network call, and the privacy notice must disclose it. Over-the-air updates (EAS Update) are not used.

## Languages

- **App text (about 150 strings).** `i18next`, `react-i18next` and `expo-localization`, with one catalog per
  language. A test fails on any missing key.
- **Method text, labels, gaps and the categorical vocabulary** are translated in the Python model, not the
  app. `document.method()` and `label()` emit a message id plus arguments, and a new `model/i18n.py` renders
  them per language. The renderer still adds nothing.
- **Facts.** A translated fact is new printed text, so it gets the full treatment:
  - it is staged in `model/translations/<lang>/`, keyed by the English fact's hash;
  - its numbers must match the English fact and the original quote (`evidence.value_in_quote`);
  - it gets its own hash and verdict, checked by the model that did not translate it;
  - if it fails, it falls back to the checked English text, marked "translation withheld".

  Each language has its own gate (`factcheck.py gate --lang`). Estimated cost: about $2–5k for 23 languages,
  after a pilot on one language.
- **The disclaimer** gains a per-language form: "this text is a machine translation of the English edition".
- **Irish and Maltese** are labelled "unreviewed machine translation" until reviewers exist.
- **Launch shape.** All 24 languages for app and method text, facts in English plus the original quote, and
  fact translations switched on language by language.

## Distribution

- **Accounts.** Apple costs €99 a year and Google Play $25 once. Until the foundation exists, these are in
  the owner's personal name. Apps can be transferred later.
- **Google's rule for new personal accounts:** a closed test with 12 testers for 14 days before production.
- **Privacy.** "Data not collected" for v1. A privacy policy page is still required.
- **EU trader declaration** (DSA): trader or non-trader is the owner's decision.
- **Until the launch gate (#50):** internal testing tracks only.
- **Review risk.** Apple guideline 4.2 (an app that looks like a repackaged website). The answer is offline
  reading and native source views.

## Build, CI, testing

- **Builds.** Expo managed, with continuous native generation. EAS builds run only from a manual,
  owner-approved workflow, `mobile-release.yml`, after `./test.sh` and the fact-check gates.
- **Proving the bundle is the checked one.** The app's copy is checked against `manifest.json` at HEAD, as
  the web smoke test checks the served bundle.
- **The gate.** `test.sh` gains a mobile stage, with a `--no-mobile` flag. CI gains `npm audit` for `mobile/`
  and a Dependabot entry.
- **Paperwork.** New decision entries for the architecture, the translation rule and the store accounts.

## Risks

- **Stale facts on installed apps,** until the edition check exists.
- **Translation cost and quality,** especially Irish and Maltese.
- **Drift between the web and app renderers.** Parity tests guard against it.
- **Store rejection,** and Google's closed-test rule.
- **Performance** on low-end phones.
- **US processors** (Expo EAS, Supabase).
- **Accounts in a personal name** until the foundation exists.
